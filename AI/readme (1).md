# AI 7차시 시험 대비 정리 (키워드 기반)

---

## 1. Post-Training

**사전학습(Pre-training) 이후** 모델을 특정 목적에 맞게 추가 학습하는 과정의 총칭

### 단계별 흐름

```
Pre-training (대규모 데이터로 기본 능력 학습)
    ↓
Instruction Tuning (지시 따르기 학습)
    ↓
RLHF (인간 피드백 기반 강화학습)
    ↓
배포 (Deploy)
```

---

## 2. Instruction Tuning 특징 ★★

**정의**: 모델이 사람의 지시(instruction)를 잘 따르도록 파인튜닝하는 기법

### 핵심 특징

| 특징 | 설명 |
|------|------|
| **입력 형식** | (instruction, input, output) 트리플렛 형태의 데이터 사용 |
| **목적** | 단순 텍스트 예측 → 지시 수행 능력 부여 |
| **데이터 효율** | 상대적으로 적은 데이터로도 효과적 |
| **일반화** | 학습 안 한 새로운 지시에도 어느 정도 대응 가능 (Zero-shot) |

**예시 데이터 형식:**
```
Instruction: 다음 문장을 영어로 번역해줘
Input: 오늘 날씨가 좋다
Output: The weather is nice today
```

> 💡 **교수님 강조 포인트로 예상**: Pre-training과의 차이 — Pre-training은 다음 토큰 예측, Instruction Tuning은 지시 수행

---

## 3. RLHF 파이프라인 ★★★

**Reinforcement Learning from Human Feedback** — 인간 피드백 기반 강화학습

### 3단계 파이프라인

**1단계: SFT (Supervised Fine-Tuning)**
- 사람이 직접 작성한 고품질 응답으로 파인튜닝
- Instruction Tuning과 유사

**2단계: 보상 모델 학습 (Reward Model Training)**
- 동일 질문에 여러 응답을 생성
- 사람이 응답 품질 순위 매김
- 이 선호도 데이터로 **보상 모델(RM)** 학습

**3단계: RL 최적화 (PPO)**
- 보상 모델을 기준으로 강화학습
- 보상이 높은 방향으로 모델 업데이트
- **PPO (Proximal Policy Optimization)** 알고리즘 주로 사용

```
질문 → LLM이 여러 응답 생성
           ↓
    사람이 순위 매김
           ↓
    보상 모델 학습
           ↓
    PPO로 LLM 최적화
```

> ⚠️ **한계**: 사람 피드백 수집 비용 높음, 보상 해킹(reward hacking) 발생 가능

---

## 4. RAG (Retrieval-Augmented Generation) 정의 ★★★

**정의**: 외부 지식 베이스에서 관련 정보를 검색(Retrieve)하여 LLM의 생성(Generate)에 활용하는 기법

### RAG가 필요한 이유

| 문제 | RAG로 해결 |
|------|-----------|
| LLM의 지식 컷오프 | 최신 정보 검색해서 활용 |
| 환각(Hallucination) | 실제 문서 기반으로 답변 |
| 기업 내부 데이터 | 외부 DB 연결하여 활용 |

### RAG 기본 파이프라인

```
질문 입력
    ↓
쿼리 임베딩 변환
    ↓
벡터 DB에서 유사 문서 검색 (Retrieve)
    ↓
검색된 문서 + 질문을 LLM에 함께 입력
    ↓
최종 답변 생성 (Generate)
```

---

## 5. Information Retrieval의 종류 ★★

### 5-1. Sparse Retrieval (희소 검색)

키워드 기반 검색 방식

| 기법 | 설명 |
|------|------|
| **TF-IDF** | 단어 빈도와 역문서 빈도로 중요도 계산 |
| **BM25** | TF-IDF 개선판, 현재도 강력한 베이스라인 |

- ✅ 빠르고 해석 가능
- ❌ 동의어, 문맥 파악 어려움

### 5-2. Dense Retrieval (밀집 검색)

임베딩 기반 의미론적 검색

| 기법 | 설명 |
|------|------|
| **DPR** (Dense Passage Retrieval) | 질문/문서를 각각 인코딩 후 유사도 계산 |
| **Bi-Encoder** | 쿼리와 문서를 독립적으로 인코딩 (빠름) |
| **Cross-Encoder** | 쿼리+문서를 함께 인코딩 (정확하지만 느림) |

- ✅ 의미적 유사성 파악 가능
- ❌ 계산 비용 높음

### 5-3. Hybrid Retrieval

Sparse + Dense를 결합하여 장단점 보완

```
BM25 결과 + Dense 결과
        ↓
    재랭킹 (Reranking)
        ↓
    최종 문서 선택
```

## 6. Tool Usage in LLMs ★★

**정의**: LLM이 외부 도구(API, 계산기, 검색엔진 등)를 호출하여 능력을 확장하는 기법

### 작동 방식

```
사용자 질문
    ↓
LLM이 어떤 Tool을 쓸지 결정
    ↓
Tool 호출 (API call 등)
    ↓
Tool 결과를 LLM에 전달
    ↓
최종 답변 생성
```

### 대표적인 Tool 종류

| Tool | 용도 |
|------|------|
| 계산기 | 수식 계산 |
| 검색 API | 최신 정보 검색 |
| 코드 실행기 | 코드 작성 및 실행 |
| 데이터베이스 | 구조화된 데이터 조회 |
| 외부 서비스 | 날씨, 지도 등 |

> 💡 LLM 단독으로는 실시간 정보, 정확한 계산이 어려움 → Tool로 보완

---

## 7. MCP (Model Context Protocol) ★★

**정의**: LLM이 외부 도구/서비스와 표준화된 방식으로 소통하기 위한 **프로토콜(통신 규약)**

Anthropic이 2024년 말 제안한 오픈 표준

### MCP가 필요한 이유

```
기존: LLM마다 다른 방식으로 Tool 연결
      → 매번 새로 개발해야 함 (비효율)

MCP: 표준 프로토콜로 한 번 연결하면
      → 어떤 LLM에도 재사용 가능
```

### MCP 구성 요소

| 구성요소 | 역할 |
|---------|------|
| **MCP Host** | LLM 애플리케이션 (Claude 등) |
| **MCP Client** | 서버와 통신하는 클라이언트 |
| **MCP Server** | 특정 Tool/데이터 제공 서버 |

### Tool Usage vs MCP 차이

| 항목 | Tool Usage | MCP |
|------|-----------|-----|
| 개념 | LLM이 도구 사용하는 능력 | 도구 연결 표준 규약 |
| 범위 | 기능적 개념 | 프로토콜/인프라 개념 |
| 비유 | "전화 통화 능력" | "전화기 표준 규격" |

## 6. RAG 유사도 계산 (7차시) ★

### 코사인 유사도

**Q. 벡터 A=[1,2,3], B=[2,1,3]의 코사인 유사도는?**

```
코사인 유사도 = A·B / (|A| × |B|)

A·B = 1×2 + 2×1 + 3×3 = 2 + 2 + 9 = 13

|A| = √(1² + 2² + 3²) = √(1+4+9) = √14 ≈ 3.742
|B| = √(2² + 1² + 3²) = √(4+1+9) = √14 ≈ 3.742

유사도 = 13 / (3.742 × 3.742)
        = 13 / 14
        ≈ 0.929

→ 1에 가까울수록 유사, 0이면 무관, -1이면 반대
```

## 7. BM25 점수 계산 (7차시) ★

**TF-IDF 기반 검색 점수 계산**

### TF-IDF 기본

**Q. 문서 100개 중 10개에 "AI"가 등장, 특정 문서에서 "AI"가 5번 등장(전체 50단어)일 때 TF-IDF는?**

```
TF = 단어 등장 횟수 / 문서 전체 단어 수
   = 5 / 50 = 0.1

IDF = log(전체 문서 수 / 해당 단어 포함 문서 수)
    = log(100 / 10) = log(10) ≈ 2.303

TF-IDF = TF × IDF
        = 0.1 × 2.303
        ≈ 0.230
```

## 1. LLM 평가 (Evaluation) ★★

### 왜 평가가 어려운가?

LLM의 출력은 **정답이 하나가 아님** → 전통적인 정확도 측정 어려움

### 평가 방식의 종류

#### 1-1. 자동 평가 (Automatic Evaluation)

| 지표 | 설명 | 한계 |
|------|------|------|
| **BLEU** | 생성 텍스트와 정답의 n-gram 겹침 측정 | 의미적 유사성 반영 못함 |
| **ROUGE** | 요약 평가에 주로 사용, 재현율 기반 | 마찬가지로 표면적 비교 |
| **Perplexity** | 모델이 텍스트를 얼마나 잘 예측하는지 | 실제 유용성과 괴리 가능 |

> 💡 **Perplexity**: 낮을수록 좋음. 모델이 다음 토큰을 얼마나 확신하는지의 역수 개념

#### 1-2. 벤치마크 평가

| 벤치마크 | 측정 대상 |
|---------|----------|
| **MMLU** | 57개 분야 지식 (수학, 법, 의학 등) |
| **HumanEval** | 코딩 능력 |
| **HellaSwag** | 상식 추론 |
| **GSM8K** | 초등 수준 수학 문제 |
| **TruthfulQA** | 사실 정확성, 환각 측정 |

> ⚠️ **벤치마크 오염(Benchmark Contamination)**: 학습 데이터에 벤치마크 문제가 포함되어 점수가 부풀려지는 문제

#### 1-3. 인간 평가 (Human Evaluation)

- **Chatbot Arena**: 두 모델의 응답을 사람이 비교하여 ELO 점수 부여
- 가장 신뢰도 높지만 비용이 크고 느림

#### 1-4. LLM-as-a-Judge

- GPT-4 등 강력한 LLM이 다른 LLM의 출력을 평가
- 인간 평가를 어느 정도 대체 가능
- ⚠️ 자기 편향(Self-bias) 존재 — 같은 회사 모델에 후한 점수 경향

## 2. LLM 발전 방향 ★★

### 주요 트렌드

| 방향 | 설명 |
|------|------|
| **멀티모달** | 텍스트 넘어 이미지, 음성, 영상 처리 |
| **컨텍스트 길이 확장** | 수십만~수백만 토큰 처리 |
| **추론 능력 강화** | Chain-of-Thought, 수학/코딩 성능 향상 |
| **경량화** | 온디바이스 구동 가능한 소형 모델 |
| **에이전트화** | 단순 응답 → 자율적 행동 수행 |

### Scaling Law의 한계와 대응

```
단순히 모델 크기만 키우는 시대 → 한계 도달
        ↓
데이터 품질, 추론 효율, 아키텍처 개선으로 방향 전환
        ↓
Test-time Compute (추론 시 더 많은 계산 투입)
예: OpenAI o1, o3 시리즈
```

## 3. AI Agent ★★★

### 정의

> LLM이 단순히 질문에 답하는 것을 넘어 **목표를 받아 스스로 계획하고, 도구를 사용하며, 행동을 실행**하는 시스템

### Agent vs 일반 LLM 차이

| 항목 | 일반 LLM | AI Agent |
|------|---------|---------|
| 동작 방식 | 질문 → 답변 (1회) | 목표 → 계획 → 실행 → 반복 |
| 도구 사용 | 제한적 | 적극적으로 Tool 활용 |
| 자율성 | 낮음 | 높음 |
| 메모리 | 없음 (단일 컨텍스트) | 장기 메모리 활용 가능 |

### Agent의 핵심 구성 요소

```
┌─────────────────────────────────┐
│           AI Agent              │
│                                 │
│  ┌─────────┐   ┌─────────────┐  │
│  │ Planning│   │   Memory    │  │
│  │ (계획)  │   │  (기억)     │  │
│  └─────────┘   └─────────────┘  │
│                                 │
│  ┌─────────┐   ┌─────────────┐  │
│  │  Tools  │   │   Action    │  │
│  │ (도구)  │   │  (행동)     │  │
│  └─────────┘   └─────────────┘  │
└─────────────────────────────────┘
```

### ReAct 패턴 (Reasoning + Acting) ★

Agent가 생각하고 행동하는 기본 루프

```
Thought: 지금 뭘 해야 할지 추론
    ↓
Action: Tool 호출 (검색, 계산 등)
    ↓
Observation: Tool 결과 확인
    ↓
Thought: 결과 보고 다시 추론
    ↓
... 반복 ...
    ↓
Final Answer: 최종 답변
```

**예시 (여행 계획 세우기):**
```
Thought: 서울에서 제주 가는 항공편을 찾아야겠다
Action: 항공 검색 API 호출
Observation: 오전 7시, 오전 10시 편 있음
Thought: 숙소도 찾아야겠다
Action: 숙소 검색 API 호출
Observation: 제주 시내 호텔 3곳 추천
Thought: 충분한 정보가 모였다
Final Answer: 여행 계획 제시
```

### Multi-Agent 시스템

여러 Agent가 역할을 분담하여 협력

```
Orchestrator Agent (총괄)
    ├── Research Agent (정보 수집)
    ├── Writing Agent (문서 작성)
    └── Review Agent (검토/수정)
```

> 💡 **장점**: 복잡한 작업을 병렬 처리, 각 Agent가 특화된 역할 수행

## 4. Memory (메모리) ★★★

### 메모리의 4가지 종류

#### 4-1. Sensory Memory (감각 메모리)
- 현재 입력되는 정보 (이미지, 텍스트 등)
- 컨텍스트 윈도우에 있는 현재 입력값
- 매우 짧게 유지됨

#### 4-2. In-Context Memory (인컨텍스트 메모리)
- **컨텍스트 윈도우 내** 의 정보
- 대화 히스토리, 현재 세션의 내용
- 컨텍스트 길이 한계 존재

#### 4-3. External Memory (외부 메모리) ← RAG와 연결
- 벡터 DB, 파일, 데이터베이스 등 외부 저장소
- 컨텍스트 한계 없이 방대한 정보 저장
- 필요할 때 검색해서 가져옴

#### 4-4. In-Weights Memory (가중치 메모리)
- 모델 학습으로 **파라미터에 내재화**된 지식
- 변경하려면 파인튜닝 필요
- 가장 영구적이지만 업데이트 어려움

### 메모리 종류 비교

| 종류 | 용량 | 지속성 | 업데이트 |
|------|------|--------|---------|
| In-Context | 작음 (토큰 제한) | 세션 중 | 즉시 |
| External | 무한대 | 영구 | 즉시 |
| In-Weights | 모델 파라미터 | 영구 | 파인튜닝 필요 |

### 인간 기억 vs AI 메모리 비유

| 인간 | AI |
|------|-----|
| 단기 기억 | In-Context Memory |
| 장기 기억 | In-Weights Memory |
| 메모장/책 | External Memory |

## 5. Tool (도구) ★★★

### Tool의 종류

| 분류 | 예시 | 용도 |
|------|------|------|
| **정보 검색** | 웹 검색, DB 조회 | 최신 정보, 외부 데이터 |
| **계산/실행** | 계산기, 코드 실행기 | 정확한 수치 계산 |
| **외부 서비스** | 날씨 API, 지도 API | 실시간 데이터 |
| **파일 시스템** | 파일 읽기/쓰기 | 문서 처리 |
| **커뮤니케이션** | 이메일, 캘린더 | 일정 관리, 메시지 전송 |

### Function Calling ★

LLM이 Tool을 호출하는 표준적인 방식

```python
# LLM에게 사용 가능한 함수 정의를 알려줌
tools = [
    {
        "name": "get_weather",
        "description": "특정 도시의 날씨를 가져옴",
        "parameters": {
            "city": "string"
        }
    }
]

# LLM이 필요 시 함수 호출 결정
# → {"name": "get_weather", "parameters": {"city": "서울"}}
# → 실제 함수 실행 → 결과를 LLM에 전달 → 최종 답변
```

### Tool 사용 시 고려사항

> ⚠️ **할루시네이션 주의**: Tool 결과를 무시하고 자체적으로 답변하는 경우 있음  
> ⚠️ **Tool 선택 오류**: 적절하지 않은 Tool을 호출하는 경우  
> ⚠️ **보안**: 외부 시스템 접근 권한 관리 필요

## 6. Deep Research ★★★

### 정의

> AI Agent가 복잡한 질문에 대해 **자율적으로 여러 단계의 검색과 추론을 반복**하며 심층적인 보고서를 생성하는 기능

| 소요 시간 | 수 초 | 수 분~수십 분 |

### Deep Research 작동 과정

```
    ↓
5. 수집된 정보 종합
    ↓
6. 구조화된 보고서 생성
```

## 5. 컨텍스트 길이 & 메모리 계산 (8차시) ★

### Attention 메모리 계산

**Q. 시퀀스 길이 1024, 히든 차원 768, 32비트 float일 때 Attention 행렬 메모리는?**

```
Attention 행렬 크기: sequence × sequence
= 1024 × 1024 = 1,048,576개

메모리: 1,048,576 × 4바이트(32비트)
= 4,194,304 bytes
= 4MB

시퀀스 길이가 2배(2048)가 되면:
2048 × 2048 × 4 = 16MB (4배 증가!)

→ Attention은 시퀀스 길이의 제곱에 비례
```

## 4. 엔트로피 계산 (8차시 / 10차시 TTA) ★

### 기본 엔트로피 공식

$$H = -\sum_k p_k \log_2 p_k$$

**Q. 모델이 [0.7, 0.2, 0.1]의 확률로 예측할 때 엔트로피는?**

```
H = -(0.7×log₂0.7 + 0.2×log₂0.2 + 0.1×log₂0.1)
  = -(0.7×(-0.515) + 0.2×(-2.322) + 0.1×(-3.322))
  = -((-0.361) + (-0.464) + (-0.332))
  = -(-1.157)
  = 1.157 bits
```

**Q. 모델이 [1.0, 0.0, 0.0]으로 완전 확신할 때 엔트로피는?**

```
H = -(1.0×log₂1.0 + 0 + 0)
  = -(1.0×0)
  = 0

→ 엔트로피 0 = 완전 확신 = 가장 좋은 상태
→ 엔트로피 높을수록 불확실 = TTA에서 걸러내야 할 샘플
```

## 1. 이진 수 체계 (Binary Number System)

컴퓨터는 전류가 흐르거나 흐르지 않는 **두 가지 상태**만 표현 가능 → 이진수가 기본 수체계

### 진수 변환 & 단위

| 단위 | 비트 수 | 근사값 |
|------|---------|--------|
| 니블(Nibble) | 4bit | 16진수 심볼 1개 |
| 바이트(Byte) | 8bit | - |
| Kilo | 2¹⁰ | ≈ 1,000 |
| Mega | 2²⁰ | ≈ 1,000,000 |
| Giga | 2³⁰ | ≈ 1,000,000,000 |

> 💡 **교수님 강조**: 2의 거듭제곱은 10승마다 10진수에서 0이 3개씩 붙는다고 이해하면 어림짐작에 유리!

### LSB / MSB

- **LSB** (Least Significant Bit/Byte): 가장 낮은 자릿수
- **MSB** (Most Significant Bit/Byte): 가장 높은 자릿수

### 16진수 (Hexadecimal)

- 이진수 4비트 묶음 = 16진수 심볼 1개
- 긴 이진 패턴을 짧게 표현 가능
- 실제 프로그래밍에서 메모리 주소 등에 자주 등장

---

## 2. 부호 있는 수 체계 (Signed Number System)

### 2-1. 부호 크기 표현 (Sign-Magnitude)

- **MSB = 부호비트** (0이면 양수, 1이면 음수)
- 나머지 비트 = 절댓값

**n비트 표현 범위:**

$$-(2^{n-1}-1) \sim +(2^{n-1}-1)$$

**4비트 예시:**

| 패턴 | 값 |
|------|----|
| 0110 | +6 |
| 1110 | -6 |
| 0000 | +0 |
| 1000 | -0 ← 문제! |

> ⚠️ **치명적 단점**: **0이 두 가지 패턴(+0, -0)** 으로 표현되어 **기존 덧셈 연산이 그대로 사용 불가**

---

### 2-2. 2의 보수 (Two's Complement) ★★★

현재 컴퓨터에서 **실제로 사용**하는 방식

**핵심 원리**: 최상위 비트(MSB)에 **-2^(n-1)** 의 가중치 부여

**n비트 표현 범위:**

$$-2^{n-1} \sim +(2^{n-1}-1)$$

**4비트 예시:**

| 패턴 | 값 |
|------|----|
| 0111 | +7 |
| 0001 | +1 |
| 0000 | 0 |
| 1111 | -1 |
| 1000 | -8 |

> ✅ **장점**: 기존 덧셈 그대로 사용 가능 / 0의 표현이 하나뿐

**부호 반전 방법**: 모든 비트 반전 후 +1

```
+3 = 0011
비트 반전 → 1100
+1 → 1101 = -3 ✓
```

---

### 2-3. 오버플로우 (Overflow)

- 연산 결과가 표현 범위를 초과하는 현상
- **부호 없는 수**: Carry Out 시그널로 감지
- **부호 있는 수 (2의 보수)**:
  - 양수 + 양수 = 음수 → 오버플로우
  - 음수 + 음수 = 양수 → 오버플로우

**4비트 예시 (11 + 6 = 17, 표현 불가):**
```
1011 (11)
+ 0110 (6)
──────
10001 → 4비트만 취하면 0001 = 1 (오답!)
```

---

### 2-4. 비트 확장 (Bit Extension)

| 방식 | 방법 | 사용 시점 |
|------|------|----------|
| **부호 확장 (Sign Extension)** | MSB를 복사하여 채움 | **값**을 유지하며 확장 |
| **제로 확장 (Zero Extension)** | 0으로 채움 | **패턴**을 유지하며 확장 |

> 💡 C에서 `char → int` 캐스팅 시 자동 적용됨 (signed/unsigned 선언에 따라 달라짐)

---

## 3. 고정 소수점 수 체계 (Fixed-Point Number System)

### 기본 개념

M비트를 **정수부(k비트) + 소수부(m비트)** 로 분리하여 해석

```
[ 정수부 k비트 | 소수부 m비트 ]
                ↑
           Binary Point (고정)
```

### 스케일링 팩터 (Scaling Factor) ★★★

> 🔑 **핵심**: 소수점 위치는 **저장하지 않는다!** 컴퓨터는 항상 정수로 인식

- 컴퓨터가 인식하는 값과 사용자가 의도한 값의 차이 = **2^m 배**
- 스케일링 팩터는 **프로그래머의 머릿속에만 존재**

### 연산 규칙 ★★ (계산 문제 출제 예상!)

| 연산 | 처리 방법 |
|------|----------|
| **덧셈/뺄셈** | 그대로 수행 가능 ✅ |
| **곱셈** | 결과에 **스케일링 팩터를 한 번 더 곱해야** 함 (오른쪽 시프트) |
| **나눗셈** | 결과에 **스케일링 팩터를 한 번 더 나눠야** 함 (왼쪽 시프트) |

**곱셈 예시 (4.4 고정소수점, 1.5 × 0.5 계산):**

```
1.5 → 패턴: 00011000 (컴퓨터는 24로 인식)
0.5 → 패턴: 00001000 (컴퓨터는 8로 인식)

그냥 곱하면: 24 × 8 = 192 → 가운데 점 찍으면 12 (오답! 정답은 0.75)

올바른 방법: 192를 2^4(=16)으로 나눔 (4비트 오른쪽 시프트)
→ 192 / 16 = 12 → 가운데 점 찍으면 0.75 ✓
```

---

## 4. 부동 소수점 수 체계 (Floating-Point Number System)

### 기본 구조

$$값 = (-1)^S \times M \times \beta^E$$

| 구성요소 | 이름 | 설명 |
|---------|------|------|
| S | 부호(Sign) | 1비트, 0=양수 1=음수 |
| M | 가수(Mantissa/Significand) | 유효숫자 |
| β (beta) | 밑(Base/Radix) | **저장하지 않음**, 사전에 약속 |
| E | 지수(Exponent) | 소수점 위치 결정 |

> 💡 **부동(浮動)의 의미**: 지수값에 따라 소수점 위치가 이동(Floating)하므로 부동소수점

### 정규화 (Normalization) ★

**목적**: 동일한 수의 표현이 여러 개가 되는 것을 방지 + 유효숫자 최대 활용

```
0.00101 × 2^5
0.0101  × 2^4  ← 비효율
0.101   × 2^3
1.01    × 2^2  ← 정규화된 표현 (1.xxx 형태 강제)
```

정규화의 장점:
1. 유효숫자 최대 활용
2. 대소 비교 시 **지수만 비교**하면 됨 (하드웨어 효율)

### 바이어스 지수 (Biased Exponent) ★

실제 저장값 = 진짜 지수 + Bias(편향값)

**이유**: 지수를 양수 영역으로 이동 → 대소 비교를 정수 비교와 동일하게 처리 가능 (하드웨어 간소화)

### 스페셜 패턴 (IEEE 754 32bit 기준)

| 지수부 | 가수부 | 의미 |
|--------|--------|------|
| 00000000 | 00...0 | **0** |
| 00000000 | ≠ 0 | **비정규화수 (Denormal)** |
| 11111111 | 00...0 | **±무한대 (±INF)** |
| 11111111 | ≠ 0 | **NaN (Not a Number)** |

---

## 5. IEEE 754 표준 ★★

### 단정밀도 (Float, 32bit)

```
[ S(1) | Exponent(8) | Fraction(23) ]
```

- 바이어스: **127**
- **히든 비트**: 정규화 수의 앞 1은 저장 안 함 → 유효숫자 1비트 추가 확보
- 실제 값: (-1)^S × **1**.F × 2^(E-127)

### 배정밀도 (Double, 64bit)

```
[ S(1) | Exponent(11) | Fraction(52) ]
```

- 바이어스: **1023**
- 최대값: 약 10^308

> 💡 **교수님 강조**: 비트 수가 두 배가 될 때 **가수부(유효숫자)를 크게 늘리는 이유** → 정밀도가 핵심이기 때문!

### 고정 소수점 vs 부동 소수점 비교

| 항목 | 고정 소수점 | 부동 소수점 |
|------|-----------|-----------|
| 표현 범위 | 좁음 | 넓음 |
| 정밀도 | 일정 | 가변 |
| 연산 속도 | 빠름 | 느림 |
| 하드웨어 복잡도 | 낮음 | 높음 |
| 오차 | 절댓값 일정 | 상대적 |

---

## 6. 연산 복잡도 비교

### 4가지 연산 속도 (느린 순)

```
덧셈 ≈ 뺄셈  <<  곱셈  <<  나눗셈
```

> ⚠️ **교수님 강조**: **나눗셈은 최대한 피해라!** 비교 + 뺄셈이 반복되어 극도로 느림

**부동소수점 특이사항**: 덧셈/뺄셈이 곱셈보다 오히려 느릴 수 있음
- 덧셈/뺄셈: 지수 정렬 → 연산 → 사후 정규화 → 오버플로우 체크 (단계가 연결됨)
- 곱셈: 부호/지수/가수 **독립적으로** 연산 가능 → 병렬 처리 유리

### 뺄셈 구현 방식

> CPU에는 **덧셈기(Adder)만 존재!**  
> 뺄셈 `a - b`는 내부적으로 `a + (-b)`로 처리

---

## 7. 모델 경량화 (Model Compression)

### 왜 필요한가?

- 모델 크기 폭발적 증가 (파라미터 10^13개 이상)
- 추론 비용 절감, 온디바이스 AI 구현 필요
- 자율주행/모바일 등 저전력 환경 요구

---

### 7-1. 양자화 (Quantization) ★★★

**핵심 개념**: 32bit Float → 8bit/4bit 정수로 변환하여 모델 사이즈 압축

#### QAT vs PTQ

| 구분 | QAT (Quantization-Aware Training) | PTQ (Post-Training Quantization) |
|------|----------------------------------|----------------------------------|
| 시점 | **학습 중** 양자화 적용 | **학습 후** 양자화 적용 |
| 정확도 | 높음 | 상대적으로 낮음 |
| 필요 조건 | 학습 데이터 필요 | 소규모 calibration 데이터만 필요 |
| 적용 대상 | CNN 등 소형 모델 | LLM (학습 데이터 미공개) |

#### Weight-only vs W&A Quantization

| 구분 | 설명 | 적합한 상황 |
|------|------|------------|
| **Weight-only** | 가중치만 양자화 | 모델이 너무 커서 GPU에 안 올라갈 때 |
| **W&A (Weight & Activation)** | 가중치 + 활성화 모두 양자화 | 긴 context length로 activation 부담이 클 때 |

#### 다양한 부동소수점 양자화 포맷

| 포맷 | 비트 | 특징 |
|------|------|------|
| FP32 | 32 | IEEE 754 표준, 기본값 |
| BF16 | 16 | FP32의 지수 범위 유지, 가수부 축소 |
| FP16 | 16 | IEEE 754 16bit, 딥러닝엔 부적합 |
| FP8 | 8 | 최신 GPU에 하드웨어 지원 내장 |

> 💡 **BF16이 FP16보다 딥러닝에 유리한 이유**: 지수 범위(레인지)를 FP32와 동일하게 유지하기 때문

---

### 7-2. 프루닝 (Pruning / 가지치기)

**핵심 개념**: 중요도가 낮은(절댓값이 작은) 가중치를 0으로 만들어 저장 생략

#### Structured vs Unstructured

| 구분 | 방식 | GPU 친화성 | 압축 효율 |
|------|------|-----------|----------|
| **Unstructured** | 임의 위치 제거 | 낮음 ❌ | 높음 ✅ |
| **Structured** | 행/열 단위 제거 | 높음 ✅ | 낮음 ❌ |

> ⚠️ **GPU와 궁합 주의**: GPU(cuSPARSE)는 약 **95% 이상** 압축 시에야 속도 이득 발생, 딥러닝 프루닝(60~80%)으로는 속도 이득 미미

#### 모델별 프루닝 한계

| 모델 종류 | 최대 프루닝률 |
|----------|-------------|
| CNN 계열 | 90~95% |
| Transformer/LLM | 60~70% |

### 7-3. 지식 증류 (Knowledge Distillation)

**핵심 개념**: 큰 모델(Teacher)이 작은 모델(Student)을 가르쳐 학습

```
[Teacher 모델] → 소프트맥스 출력 비교 → [Student 모델]
                                              ↑
                           정답 데이터와의 오차도 함께 학습
Total Loss = Student Loss + Distillation Loss
```

> 💡 **교수님 강조**: Teacher와 Student의 **역량 차이가 너무 크면** 효율 저하 → 중간 **Assistant 모델** 활용

## 8. Fine-Tuning (파인튜닝) ★★★

### 방법 비교

| 방식 | 설명 | 장점 | 단점 |
|------|------|------|------|
| **In-Context Learning** | 프롬프트만 수정 | 비용 없음 | 표현력 한계 |
| **Full Fine-Tuning** | 전체 가중치 업데이트 | 특화 성능 최고 | 비용 폭발, 망각 발생 |
| **Adapter** | 레이어 추가 후 추가 레이어만 학습 | 표현력 우수 | 여전히 비쌈 |
| **Prompt Tuning** | 임베딩 앞부분만 학습 | 매우 저렴 | 표현력 부족 |
| **LoRA** ⭐ | 저랭크 행렬 추가 | 효율/성능 균형 | - |

---

### 8-1. LoRA (Low-Rank Adaptation) ★★★

**핵심 아이디어**: 원본 가중치 행렬 W(d×d)를 고정하고, **두 개의 작은 벡터 A(d×r), B(r×d)** 만 추가하여 학습

```
원본 W (1000×1000) = 1,000,000개 파라미터 학습 필요
                         ↓ LoRA 적용
A (1000×1) + B (1×1000) = 2,000개만 학습!
→ A × B = W와 동일한 차원의 보정 행렬 생성
```

r(rank) 값이 클수록:
- 표현력 ↑, 특화 성능 ↑
- 학습 비용 ↑

---

### 8-2. QLoRA ★★★

**핵심 아이디어**: **양자화(Quantization) + LoRA** 결합

```
원본 모델 (16bit FP)
    ↓ 4bit로 양자화 (고정, 학습 안 함)
4bit 양자화 모델 + LoRA 벡터 (16bit FP, 학습)
    ↓ calibration 데이터로 Fine-tuning
4bit 수준 모델 크기 + 원본 수준 정확도 복원
```

> ✅ 경량화(4배 압축)와 파인튜닝(정확도 복구)을 동시에 달성

> ⚠️ **파인튜닝 ≠ 경량화**: 파인튜닝은 **특정 도메인 특화**가 목적, 추론 속도 향상이 목적이 아님!

## 3. 부동 소수점 (IEEE 754) ★★★ 가장 출제 가능성 높음

### IEEE 754 단정밀도(32비트) 구조

```
[ S(1비트) | Exponent(8비트) | Fraction(23비트) ]

S: 부호 (0=양수, 1=음수)
Exponent: 실제 지수 + 127 (바이어스)
Fraction: 가수 (히든 비트 1 제외하고 저장)
```

### 유형 5: 십진수 → IEEE 754 변환 ★

**Q. 십진수 -6.75를 IEEE 754 단정밀도로 표현하라**

```
Step 1. 이진수 변환
6.75 → 110.11

Step 2. 정규화 (1.xxxx × 2^n 형태로)
110.11 = 1.1011 × 2²

Step 3. 각 필드 채우기
S = 1 (음수)
Exponent = 2 + 127 = 129 = 10000001
Fraction = 1011 + 0으로 23비트 채우기
         = 10110000000000000000000

정답:
1 | 10000001 | 10110000000000000000000
```

### 유형 6: IEEE 754 → 십진수 변환 ★

**Q. 다음 IEEE 754 비트 패턴의 값은?**
`0 10000010 10100000000000000000000`

```
S = 0 → 양수
Exponent = 10000010 = 130
실제 지수 = 130 - 127 = 3

Fraction = 10100000000000000000000
히든 비트 포함: 1.101

값 계산:
1.101 × 2³ = 1101.0 = 13.0

정답: +13.0
```

### 유형 7: 특수값 판별

**Q. 다음 패턴이 나타내는 값은?**

```
0 11111111 00000000000000000000000
→ S=0, Exp=255(전부 1), Fraction=0
→ +무한대 (+∞)

1 11111111 00000000000000000000000
→ -무한대 (-∞)

X 11111111 (Fraction ≠ 0)
→ NaN

0 00000000 00000000000000000000000
→ +0
```

## 2. 일반적 양자화 vs 100% 정수 연산 양자화

### 핵심 개념 정리

> **일반적 양자화**: 값(value)을 실수 → 정수로 변환  
> **100% 정수 연산 양자화**: 연산 과정(process) 자체도 정수만 사용

**왜 값 양자화만으로 부족한가?**

양자화 수식: $r = S(q - Z)$

- $q$: 정수 (양자화된 값)
- $Z$: 정수 (오프셋)
- $S$: **실수** ← 이게 문제!

스케일링 파라미터 S는 나눗셈 결과이므로 반드시 실수 → 연산 과정에 실수가 개입 → **가속기 사용 불가**

---

## 3. 스케일링 파라미터 (Scaling Parameter) ★★★

### 양자화 기본 공식

$$S = \frac{r_{max} - r_{min}}{2^n - 1}$$

$$Z = \left\lfloor \frac{-r_{min}}{S} \right\rfloor$$

| 파라미터 | 이름 | 의미 | 타입 |
|---------|------|------|------|
| S | 스케일링 파라미터 | 실수 1칸당 뛰는 크기 (스텝 사이즈) | **실수** |
| Z | 오프셋 파라미터 | 좌우 이동값 | 정수 |
| q | 양자화된 값 | 0~255 사이 정수 | 정수 |

**8비트 양자화 시:**
- 관심 범위 $[r_{min}, r_{max}]$를 **255등분**
- $r_{min}$ → 0, $r_{max}$ → 255 매핑
- 범위 밖 값: 강제로 0 또는 255에 클리핑

---

## 4. 100% 정수 연산 양자화 3가지 기법 ★★★

### 기법 1: 실수 파트 묶기 (Grouping)

행렬 곱 $R_3 = R_1 \times R_2$에서 각각 양자화되어 있을 때:

$$Q_3 = Z_3 + \underbrace{\frac{S_1 S_2}{S_3}}_{M \text{ (실수)}} \sum_j (Q_1 - Z_1)(Q_2 - Z_2)$$

- $S_1, S_2, S_3$가 각각 실수이지만 → **하나의 M으로 묶음**
- 나머지는 모두 정수 → M만 해결하면 됨

> ✅ **첫 번째 기법**: 실수끼리만 묶어서 M으로 만들어라

---

### 기법 2: 비트 시프팅 (Bit Shifting) ★★★

**문제**: M의 값이 대부분 0~1 사이 → 정수 양자화 불가

**해결 3단계:**

```
1. 스케일 업: M × 2^n  (비트를 왼쪽으로 n번 이동)
2. 양자화: 소수점 버리고 정수로 변환
3. 스케일 다운: ÷ 2^n  (비트를 오른쪽으로 n번 이동)
```

> 💡 **핵심**: 2의 거듭제곱 곱셈/나눗셈 = 비트 시프트 → 연산 부담 거의 없음

**계산 예시:**

```
M = 0.34 (0~1 사이라 양자화 어려움)
n = 8로 설정

스케일 업: 0.34 × 256 = 87.04
양자화:    87 (소수점 버림)
연산 수행 후
스케일 다운: 87 >> 8 (비트를 오른쪽으로 8번 이동) = 정수 결과
```

---

### 기법 3: 배치 정규화 계층 폴딩 (BN Folding)

**문제**: BatchNorm 연산 $y = \gamma \frac{x-\mu}{\sigma} + \beta$에서 나눗셈/루트가 포함되어 실수 연산 발생

**해결**: BN을 앞/뒤 레이어에 분해해서 흡수(접어버림)

$$W_{fold} = \frac{\gamma \cdot W}{\sigma}$$

$$b_{fold} = \beta - \frac{\gamma \cdot \mu}{\sigma}$$

- 나눗셈($\sigma$로 나누기) → **가중치 W에 미리 흡수**
- 뺄셈($\mu$ 빼기) → **바이어스 b에 흡수**
- 결과: BN 레이어가 사라지고 W_fold, b_fold만 양자화하면 됨

> ✅ **세 번째 기법**: 별도 연산을 4칙연산으로 쪼개 인접 레이어에 흡수

---

### 비전 트랜스포머의 추가 연산 양자화

| 연산 | 문제점 | 해결법 |
|------|--------|--------|
| Softmax | 지수함수 포함 | 밑을 e→2로 변환 후 정수/소수부 분리 |
| GELU | 복잡한 적분 포함 | Sigmoid로 근사 후 비트시프팅 적용 |
| LayerNorm | 루트 연산 포함 | 뉴턴 메소드로 반복 근사 |

> 💡 **공통 철학**: 새로운 연산이 나올 때마다 → **묶기 + 비트시프팅**으로 정복

## 5. 스케일링 법칙과 초거대 AI ★★

### 스케일링 법칙 (Scaling Law)

**모델 크기 + 학습 데이터량 + 컴퓨팅 자원** 이 세 가지가 모두 늘어나면 성능도 비례하여 향상

> "네가 뭘 좋아할지 몰라서 다 준비했어" — 초거대 AI의 핵심 철학

**분포 이동 문제 해결 방식:**
- 학습 데이터를 너무너무 많이 모아서 → 테스트 데이터와의 분포 차이가 거의 없도록
- 하지만 비용(돈, 에너지, 시간, 프라이버시)이 폭발적으로 증가

### 초거대 AI의 한계

1. 학습 비용 폭발 (GPT-4 학습 비용 약 1천만 달러 이상)
2. 피지컬 AI 환경에서 변수 폭발 (환경+로봇행동+센서 파라미터)
3. 데이터 수집 시 프라이버시 및 환경 문제

## 6. 분포 이동 (Distribution Shift) ★★

**정의**: 학습 데이터 분포와 실제 테스트 데이터 분포가 달라지는 현상

**예시:**
```
훈련: 깨끗한 고화질 이미지 (정확도 97%)
테스트: 블러 처리된 이미지 (정확도 68%)
```

**분포 이동에 대응하는 두 가지 전략:**

| 전략 | 방법 | 특징 |
|------|------|------|
| **모델 일반화** | 지식 영역 확대 (초거대 AI) | 비용 폭발 |
| **적응적 센싱** | 테스트 분포를 학습 분포로 끌어당김 | 분포 이동 억제 |

## 7. TTA (Test-Time Adaptation) — CNN 기반 ★★★

**정의**: 라벨 없는 테스트 데이터를 활용하여 모델을 실시간으로 적응시키는 기법

**핵심 도전**: 테스트 데이터에는 라벨이 없음 → 지도 학습 불가 → 엔트로피를 손실 함수로 사용

### 7-1. TENT (기본 TTA 기법) ★

**방법:**
1. BatchNorm의 $\mu$, $\sigma$ → 테스트 데이터로 즉시 업데이트 (역전파 불필요)
2. 어파인 파라미터 $\gamma$, $\beta$ → **엔트로피 최소화**로 역전파 업데이트

**손실 함수:**
$$L = -\sum_k p_k \log p_k \quad \text{(엔트로피)}$$

> ✅ 모델 메인 가중치는 전혀 건드리지 않음 → BN 파라미터만 업데이트

**한계**: 이상치/노이즈 데이터도 모두 신뢰하여 학습 → 불안정

---

### 7-2. SAR (안정화된 TTA 기법) ★

TENT의 불안정성을 해결한 두 가지 개선:

**개선 1: 샘플 필터링**
- 엔트로피가 임계값보다 높은 샘플 = 이상치로 판단 → 적응에서 제외
- "아예 모르겠는 데이터는 배우지 않는다"

**개선 2: 손실 평탄화 (Loss Smoothing)**
- 현재 값과 이전 값의 차이가 너무 크지 않도록 정규화
- 이상한 로컬 미니마에 빠지는 것 방지

| 항목 | TENT | SAR |
|------|------|-----|
| 샘플 선택 | 모두 사용 | 엔트로피 기준 필터링 |
| 학습 안정성 | 낮음 | 높음 |
| 구현 복잡도 | 낮음 | 높음 |

---

## 8. VLM 기반 TTA (PromptAlign) ★★★

**배경**: CLIP 같은 비전-언어 모델에서 분포 이동 대응

### 8-1. TPT (Test-time Prompt Tuning)

**핵심 아이디어**: 이미지 1장을 증강하여 다수의 뷰 생성 → 신뢰도 높은 것만 선택 → 텍스트 프롬프트 튜닝

**과정:**
```
이미지 1장 입력
    ↓
다양한 증강 (27개)
    ↓
엔트로피 낮은 상위 6개 선택 (SAR 철학 동일)
    ↓
6개의 평균 엔트로피로 손실 계산
    ↓
텍스트 프롬프트만 역전파로 업데이트
(모델 파라미터는 동결)
```

> ✅ 모델 전혀 안 바꿈, **텍스트 프롬프트만** 조정

---

### 8-2. PromptAlign ★★★

TPT에서 **이미지 인코더 쪽 프롬프트도 추가로 튜닝**

**추가된 핵심 아이디어: 계층별 통계 정렬**

```
소스 도메인(학습) 데이터의 각 레이어별 평균/분산 저장
    ↓
테스트 데이터가 각 레이어 통과 시 평균/분산 산출
    ↓
소스 vs 테스트 평균/분산 차이를 손실로 설정
    ↓
이미지 프롬프트 업데이트 (테스트 분포 → 소스 분포로 당김)
```

| 기법 | 텍스트 프롬프트 | 이미지 프롬프트 | 정렬 방식 |
|------|--------------|--------------|----------|
| TPT | ✅ 업데이트 | ❌ 고정 | 엔트로피 최소화 |
| PromptAlign | ✅ 업데이트 | ✅ 업데이트 | 엔트로피 + 계층별 통계 정렬 |

## 9. 적응적 센싱 (Adaptive Sensing) ★★★

### 핵심 철학

> "눈이 나쁘면 공부를 더 하는게 아니라 **안경을 쓴다**"

**초거대 AI 방식 vs 적응적 센싱 방식:**

| 방식 | 접근법 | 비유 |
|------|--------|------|
| 초거대 AI | 모델의 지식 영역을 넓힘 | 어두운 상황 사진 100만장 공부 |
| 적응적 센싱 | 센서가 AI 친화적 데이터를 제공 | 헤드라이트 켜고 운전 |

**적응적 센싱의 효과:**
- 분포 이동을 **억제** (모델을 바꾸는게 아님!)
- 테스트 데이터를 학습 데이터 분포로 **강제 매핑**
- 센서 파라미터 조정 (ISO, 셔터스피드, 조리개 등)

### LENS 기법

```
동일한 피사체를 다양한 카메라 파라미터로 여러 장 촬영
    ↓
모든 이미지를 배치로 모델에 추론
    ↓
컨피던스 스코어(Softmax 최댓값)가 가장 높은 이미지 선택
    ↓
선택된 이미지의 결과를 최종 예측으로 사용
```

> ✅ 모델 적응 없음, 데이터 증강 없음 — **실제 물리적 재촬영**으로 최적 입력 탐색

**실험 결과:**
- 오픈 클립(초거대) 대비 파라미터 50배 작은 모델 + LENS 적용 → **4~10% 정확도 향상**
- 초거대 AI 모델에도 LENS 적용 시 **추가 8.5% 향상**

## 10. 도메인 전문 지식 주입 (Domain Knowledge Injection)

### 핵심 주장

> AI 전문 지식만으로 부족하다. **응용 분야의 전문 지식**을 모델에 직접 주입하면 경량 모델로도 높은 성능 가능

**인덕티브 바이어스(Inductive Bias)의 예시 — CNN:**
- **스페이셜 로컬리티**: 가까운 위치의 픽셀이 더 연관성 높음 → 작은 필터 사용
- **포지셔널 인베리언스**: 위치가 달라도 같은 특징 추출 가능 → 동일 필터 재사용

### 수면 의학 AI 사례 1 — 자동 채점

**도메인 지식 주입 3가지:**

1. **문제 재정의**: 수면 기사가 '눈으로 보고' 채점한다는 사실 → 시계열 문제를 **컴퓨터 비전 문제**로 전환 (파형 스크린샷 찍기)

2. **모델 선택**: 생체 신호의 y축 위치는 연관성과 무관 → CNN 대신 **비전 트랜스포머** 사용 (포지셔널 임베딩으로 각 신호 독립 처리)

3. **맥락 반영**: 수면 기사는 전후 에폭을 함께 고려 → **에폭 간 트랜스포머**로 전후 관계 모델링

### 수면 의학 AI 사례 2 — 무호흡 진단

**핵심 도메인 지식:**
- 무호흡 지속 시 → 몸이 살기 위해 큰 움직임 발생 = **호흡 각성 이벤트**
- 호흡 각성은 무호흡보다 움직임이 크고 30초 이내 — 감지 쉬움

**전략 전환:**
```
기존: 무호흡/저호흡 직접 감지 → 영상으로 어렵고 느림
변경: 호흡 각성 감지 후 백트래킹으로 무호흡 추정 → 빠르고 가벼움
```

**결과:** 5시간 수면 분석에 8시간 걸리던 것 → **실시간 처리** 가능 (30초 클립 분석에 16초)

# 계산 문제 예상 유형 추가 정리

## 1. 양자화 계산 (10차시) ★★★

### 스케일링 파라미터 S, Z 계산

**Q. 실수 범위 [-1.0, 1.0]을 8비트 정수(0~255)로 양자화할 때 S와 Z를 구하라**

```
S = (r_max - r_min) / (2^n - 1)
  = (1.0 - (-1.0)) / 255
  = 2.0 / 255
  ≈ 0.00784

Z = floor(-r_min / S)
  = floor(1.0 / 0.00784)
  = floor(127.55)
  = 127

정답: S ≈ 0.00784, Z = 127
```

### 실수 → 정수 양자화

**Q. 위 파라미터로 실수값 0.5를 양자화하라**

```
q = round(r / S + Z)
  = round(0.5 / 0.00784 + 127)
  = round(63.77 + 127)
  = round(190.77)
  = 191

정답: q = 191
```

### 정수 → 실수 역양자화 (De-quantization)

**Q. 위 파라미터로 정수 191을 역양자화하라**

```
r = S × (q - Z)
  = 0.00784 × (191 - 127)
  = 0.00784 × 64
  ≈ 0.502

정답: ≈ 0.5 (양자화 오차 존재)
```

### 비트 시프팅 계산 ★

**Q. M = 0.34를 n=8로 비트 시프팅 양자화하라**

```
Step 1. 스케일 업
M × 2^8 = 0.34 × 256 = 87.04

Step 2. 소수점 버리기 (양자화)
floor(87.04) = 87

Step 3. 나중에 스케일 다운 시
87 >> 8 = 87 / 256 ≈ 0.34

정답: 양자화된 M = 87 (정수)
      실제 사용 시 >> 8 연산으로 복원
```

## 2. 행렬 곱 양자화 계산 (10차시) ★★

### M 값 계산

**Q. S1=0.5, S2=0.25, S3=0.1일 때 M을 구하고 n=4로 비트시프팅하라**

```
M = S1 × S2 / S3
  = 0.5 × 0.25 / 0.1
  = 0.125 / 0.1
  = 1.25

→ M이 1 이상이면 바로 정수 양자화 가능
  round(1.25) = 1

만약 M < 1이었다면:
M × 2^4 = M × 16
floor 취하고 나중에 >> 4
```
